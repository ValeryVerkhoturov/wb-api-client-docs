# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this project is

A [VitePress](https://vitepress.dev) documentation site for
[wb-api-client](https://github.com/ValeryVerkhoturov/wb-api-client) — auto-generated
SDKs for the Wildberries Seller API in Python, TypeScript, Go, Java, PHP, OneScript, and C#.
Deployed to GitHub Pages on every push to `main` (`.github/workflows/deploy.yml`).

## Commands

```bash
npm install
npm run docs:dev      # dev server → http://localhost:5173/wb-api-client-docs/
npm run docs:build    # production build → docs/.vitepress/dist
npm run docs:preview  # serve the built site
npm run format        # prettier --write .
npm run format:check  # prettier --check .
```

Always run `npm run format` and `npm run docs:build` before finishing a change.
The build must pass — the `buildEnd` hook in `docs/.vitepress/config.ts` also writes
the Markdown mirrors and `llms.txt`, so a broken build means broken output, not just broken HTML.

## Layout

```
docs/
  index.md                # landing page (Russian)
  guides/                 # quickstart, authentication, error-handling, custom-headers
  languages/              # one page per SDK language
  reference/              # versioning, architecture, contributing + api/
  reference/api/          # GENERATED — do not edit (see below)
  en/                     # English mirror of everything above
  public/                 # favicons, og images, robots.txt
  .vitepress/
    config.ts             # nav, sidebar, base, SEO, locales (both RU and EN live here)
    api-sidebar.ts        # GENERATED — do not edit
    llms.ts, page-meta.ts # build-time helpers for Markdown mirrors / SEO
```

## Rules that matter

### Generated content — do not hand-edit

`docs/reference/api/`, `docs/en/reference/api/`, and `docs/.vitepress/api-sidebar.ts`
are generated by `scripts/gen-api-reference.py` in the **wb-api-client** repo and pushed
here automatically. Fixes belong in that generator, not here. The generator formats its
output with this repo's pinned Prettier, so these files are NOT excluded from
`npm run format:check`.

### Two locales, kept in parity

The root locale is **Russian** (primary audience); `docs/en/` is the English mirror.
Any new or renamed page must exist in both locales:

1. Create `docs/<path>.md` (Russian) and `docs/en/<path>.md` (English).
2. Register it in the sidebar/nav for **both** locales in `docs/.vitepress/config.ts`.
3. Use locale-aware links: `/guides/...` in Russian pages, `/en/guides/...` in English.

The config's `transformPageData` pairs locales by path for hreflang/canonical tags —
mirrored paths are what make that work, so keep them identical below `en/`.

### Page conventions

- Start each content page with an H1, then a one-sentence lead paragraph. The lead is
  extracted (`page-meta.ts`) as the page description/og:description, so it must stand alone.
- Multi-language code samples use VitePress `::: code-group` blocks with one fenced block
  per language (see `docs/guides/quickstart.md` for the pattern). Language order:
  Python, TypeScript, Go, Java, PHP, OneScript, C#.
- Set frontmatter `title` when the H1 is long; a bare `description` in frontmatter
  overrides the extracted lead.
- Code repo links point at `https://github.com/ValeryVerkhoturov/wb-api-client`
  (`CODE_REPO` constant in the config).

### Style

- Formatting is Prettier with `proseWrap: "preserve"` and
  `embeddedLanguageFormatting: "off"` (`.prettierrc.json`) — don't reformat prose to a
  fixed line width, and don't manually rewrap code blocks inside Markdown.
- Comments in config/helper files follow an existing style: short paragraphs explaining
  _why_, not _what_. Match it.
- Never put real WB API tokens in examples; use placeholders like `<ваш JWT WB>` / `<your WB JWT>`.
